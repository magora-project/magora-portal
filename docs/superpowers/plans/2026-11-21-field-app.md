# Magora Field App, Phase 0 and Phase 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, with a fresh reviewer on each task by depth (`.claude/rules/process.md`, stage 6). Use superpowers:executing-plans only if the user explicitly asks for in-session execution; keep the per-task reviewer and name the departure in the PR description. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the public `magora-field-app` repo with a cloud-safe harness and local stack, then build the Phase 1 app (sign-in, the Listen loop, Map, Place, Today, Journal) against it.

**Architecture:**
- An Expo (React Native and TypeScript, Expo Router) app talks to the existing Magora backend through the contract in spec §3.
- Every cloud session and CI run uses a throwaway local Supabase in Docker. It is built from a pinned portal commit, using an interim contract schema until the Spec 2 baseline lands.
- A local fake drains the `audio_inference` queue in place of the Fly.io BirdNET worker, and answers `/api/insight`.

**Tech Stack:** Expo SDK (latest stable at Task 2), Expo Router, TypeScript, `@supabase/supabase-js` v2, `expo-audio`, Jest with `jest-expo` and `@testing-library/react-native`, Playwright (Expo web smoke), Supabase CLI, Node 22.

**Spec:** `docs/superpowers/specs/2026-11-21-field-app-design.md` (in magora-portal until Task 1 copies it into the app repo).

**Where paths point:**
- Every Files path in Tasks 2–17 is in **magora-field-app**, not in this repo. Plan review's typed reference check reads paths against magora-portal, so it reports app files whose names also exist here (for example `package.json`) as already existing.
- Those reports are recorded on the plan record as `reclassified-nit` findings, with that reason.
- An `existing` line marked "(magora-portal, at the pin)" is a magora-portal file, read at the commit in `portal-pin.txt`. In prose, `portal:` marks the same.

## Global Constraints

- The app adds **no backend** in Phase 1; any backend change is proposed as a magora-portal issue (spec §3, §4.4).
- No secret is held in the app repo or the cloud environment (spec §1, criterion 5).
- Never point the app at a real Supabase URL or the production portal from a cloud session or CI (spec §4.4).
- Cloud sessions push only `claude/*` branches and open PRs as drafts; never push to, merge into, or change settings on `main` (spec §4.4).
- Every task names a test that runs against the local stack (spec §4.4).
- Recording length: 15 s to 5 min (spec §1).
- Listen rows are identical in shape to the portal's: `mobile_detections` insert with `status: 'pending'`, `published: false`, audio in bucket `temp-audio` at `{uid}/{id}.{ext}` via `storage-upload` (portal: `src/lib/listenQueue.js`, `src/lib/listen.js`).
- Tokens come from DESIGN.md v4 (`design/DESIGN.md`, 0 VALID, 2026-11-21); the app name is "Magora".
- Device builds (EAS) run only on David's or Noah's machine (spec §4.3).

## Review Focus

1. **Recording interrupted** (call, app backgrounded, screen locked). The recording keeps going with the screen locked. A real interruption ends the take with what was captured if it is at least 15 s, and otherwise discards it with a message. It never ends in a silent empty upload. Pinned in Task 12.
2. **Upload fails or the network drops between upload and insert.** No `pending` row is created without audio. A retry reuses the same Listen id, so it never creates two rows for one recording. Pinned in Task 11.
3. **The worker never completes, or sets `failed`.** After 3 minutes of polling, the result screen shows "Still listening — we'll keep checking" with a way back. `failed` shows a retry-free message. Neither ever spins forever. Pinned in Task 11 (the poll) and Task 13 (the screen).
4. **Signed out, a person taps Listen.** They can record. Sign-in is asked for only before upload, and the take survives the sign-in. Pinned in Task 13.
5. **Location denied.** The Listen still records. Posting needs a location, so the result offers "Allow location" or "Keep private". A row is never inserted with a 0,0 location. Pinned in Task 13.
